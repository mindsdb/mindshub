API Reference

Agents API

Launch agents to perform all kinds of tasks programmatically. These agents can run on our cloud, or anywhere you choose by installing the open-source Cowork server.

Base URL
https://cowork.mindshub.ai/api/v1 Get API Key

It's straightforward: agents' work is organized in projects, where agents execute tasks. For an agent to do real work, it needs code execution environments — we call these scratchpads — and the output of a task (apps, reports, documents, and more) is organized as artifacts. Agents also draw on common resources to execute tasks: connectors to apps and data sources, files, memories, and skills.

Tasks

Manage tasks. Each task holds an ordered list of messages exchanged with the agent. Tasks and Conversations are the same concept — every task is a conversation with an assigned agent, and the same objects are available at /tasks and /conversations.

POST https://cowork.mindshub.ai/api/v1/tasks Create a task

Body

topicstringoptionalThe task's opening prompt. Also used to auto-generate the title if title is omitted.
titlestringoptionalHuman-readable name. Falls back to topic, then "Untitled task".
projectstringoptionalProject name to attach to. Ignored if project_id is set. Defaults to your account's default project if both are omitted.
project_idstringoptionalProject ID to attach to.
harnessstringoptionalAgent harness to run this task with, overriding the account default (e.g. anton).
modelstringoptionalModel override for this task. Persisted, so a reopened task remembers the pick.
curl
curl -X POST https://cowork.mindshub.ai/api/v1/tasks \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"project_id":"proj_xyz","title":"Q2 analysis","topic":"Analyse Q2 revenue by region"}'

Response — Task object

json
{
  "id":               "task_abc123",
  "title":            "Q2 analysis",
  "preview":          "Q2 analysis",
  "project":          "Sales Automation",
  "project_id":       "proj_xyz",
  "project_path":     "/Users/you/cowork/sales-automation",
  "harness":          "anton",
  "model":            "claude-opus-4-8",
  "reasoning_effort": null,

Streaming a task

The /responses endpoints send a message into a task and stream the agent's reply. Compatible with the shape of the OpenAI Responses API. Turns run detached from the connection that started them — closing the tab does not stop the run. Reconnect at any time with GET /responses/tail and resume exactly where you left off, or replay the whole turn from the start with from_seq=0. Only an explicit POST /responses/cancel stops the run.

Non-streaming response

json
{
  "id":         "resp_abc123",
  "object":     "response",
  "status":     "completed",   // "created" | "in_progress" | "completed"
  "error":      null,
  "model":      "claude-opus-4-8",
  "output": [
    {
      "type":    "message",
      "id":      "msg_1",
      "status":  "completed",
      "role":    "assistant",
      "content": [{ "type": "output_text", "text": "Here is the summary..." }]
    }
  ],
  "created_at": 1750000000
}

Streaming (SSE) events

text
data: {"type":"response.created","sequence_number":0,"response":{"id":"resp_abc123","status":"created","output":[]}}

data: {"type":"response.output_text.delta","sequence_number":1,"response":{"item_id":"msg_1","delta":"Here is "}}

data: {"type":"response.completed","sequence_number":2,"response":{"id":"resp_abc123","status":"completed","output":[/* full message */]}}
POST https://cowork.mindshub.ai/api/v1/responses Send a message and stream the reply

Body

conversationstringoptionalTask/conversation ID to append to. Omit to start a new task — pass project or project_id to place it.
inputstringrequiredUser message text.
projectstringoptionalProject name for a new task, when conversation is omitted.
project_idstringoptionalProject ID for a new task, when conversation is omitted.
streambooleanoptionalDefault false. Set true to receive the Server-Sent Events shown above; otherwise a single JSON response is returned once the turn completes.
modelstringoptionalOverride the account's model for this turn only.
reasoning_effortstringoptionalOverride the account's reasoning effort for this turn only.
harnessstringoptionalOverride the account's default harness for this turn only (e.g. anton).
curl
curl -X POST https://cowork.mindshub.ai/api/v1/responses \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"conversation":"conv_xyz","input":"Summarise last week'\''s sales data","stream":true}'

Response — see "Non-streaming response" / "Streaming (SSE) events" above

json
{ "id": "resp_abc123", "status": "completed", /* ... */ }
GET https://cowork.mindshub.ai/api/v1/responses/tail Resume a task's stream

Reconnect to an in-flight (or just-finished) turn: replay from from_seq, then live-tail new output until the turn ends. Pass from_seq=0 to replay a task's whole turn from the beginning, or the last sequence number you rendered to resume without re-rendering anything. 404 means no buffer is registered for this task — fall back to GET /tasks/{id}/items for the persisted history.

Query parameters

conversation_idstringrequiredTask/conversation to tail.
from_seqintegeroptionalDefault 0. Records with seq >= from_seq are replayed, then the connection live-tails.
curl
curl "https://cowork.mindshub.ai/api/v1/responses/tail?conversation_id=conv_xyz&from_seq=0" \
  -H "Authorization: Bearer YOUR_API_KEY"   # from the start
curl "https://cowork.mindshub.ai/api/v1/responses/tail?conversation_id=conv_xyz&from_seq=12" \
  -H "Authorization: Bearer YOUR_API_KEY"  # resume from where you left off

Response — same SSE stream shown above

text
data: {"type":"response.output_text.delta","sequence_number":12,"response":{"item_id":"msg_1","delta":"...continuing from seq 12..."}}
GET https://cowork.mindshub.ai/api/v1/responses/in-flight-list List every task with a stream currently running

No query parameters — returns every in-flight task visible to the caller, so a client can resync stream state across tabs or after a reload.

curl
curl "https://cowork.mindshub.ai/api/v1/responses/in-flight-list" \
  -H "Authorization: Bearer YOUR_API_KEY"

Response

json
{
  "in_flight": [
    { "conversation_id": "conv_xyz", "turn_id": 4, "latest_seq": 12 }
  ]
}
GET https://cowork.mindshub.ai/api/v1/responses/in-flight Check whether a specific task has a stream running

Query parameters

conversation_idstringrequiredTask whose active stream to check.

Returns latest_seq — pass it as from_seq to /responses/tail to resume without re-rendering anything already shown, or 0 to replay from the start.

curl
curl "https://cowork.mindshub.ai/api/v1/responses/in-flight?conversation_id=conv_xyz" \
  -H "Authorization: Bearer YOUR_API_KEY"

Response

json
{
  "in_flight":  true,
  "has_buffer": true,
  "latest_seq": 12,
  "turn_id":    4
}
POST https://cowork.mindshub.ai/api/v1/responses/cancel Stop a running task

Closing the connection does not stop the run — only this does.

Body

conversation_idstringrequiredTask to cancel.
curl
curl -X POST https://cowork.mindshub.ai/api/v1/responses/cancel \

  -H "Content-Type: application/json" \
  -d '{"conversation_id":"conv_xyz"}'

Scratchpads

Notebook-style workspaces scoped to a task. A scratchpad is made up of ordered cells — the agent writes to cells as it reasons, drafts, and executes code. Each cell has a type (markdown, code, or output) and tracks its own execution state. Scratchpads persist for the lifetime of the task and can be promoted to an Artifact.

Cell object

json
{
  "id":        "cell_001",
  "type":      "code",          // "markdown" | "code" | "output"
  "content":   "df.describe()",
  "language":  "python",        // present when type = "code"
  "status":    "success",       // "pending" | "running" | "success" | "error"
  "outputs":   [                 // present when type = "output"
    {
      "mime":    "text/plain",
      "data":    "count    12.0\nmean     4.2\n..."
    },
    {
      "mime":    "image/png",
      "data":    "data:image/png;base64,..."
    }
  ],
  "error":     null,            // error message when status = "error"
  "index":     0                 // display order within the scratchpad
}

type — markdown cells are prose written by the agent; code cells are executable snippets; output cells are the results attached to the preceding code cell (stdout, images, tables).
status — only relevant on code cells. pending means queued, running means currently executing, success/error are terminal states.
outputs — multi-modal: a single code cell can produce several output objects with different MIME types (plain text, HTML, PNG charts, JSON).
